## Defects found and fixed during local validation

1. A Windows `taskkill` strategy left a descendant running in this environment.
   It was replaced with suspended launch, Job Object assignment, and resume.
   Descendant cleanup and fail-closed assignment tests now pass.
2. Installing a wheel compiled fixture `.py` files into `__pycache__`, changing
   naïve source-tree fingerprints. These caches are excluded from fixture
   identities and never copied into executed snapshots. A real installed-wheel
   smoke run now passes.
3. Windows JSON newline conversion could change fixture hashes on a Linux Git
   checkout. JSON generation now explicitly uses LF; sealed evidence is marked
   `-text` to preserve raw log bytes. Git clean-filter checks pass.
4. A local build-tool issue interpreted braces in the sandbox's temporary path
   as interpolation variables. Building with a project-local TEMP/TMP directory
   resolved it without modifying system settings or package source behavior.

## Reproduce the checks

From an environment installed according to the root README:

```sh
python -m pytest -q --junitxml=test-results.xml
python -m patchreplay demo --output demo-output
python -m patchreplay check demo-output/claim-suite-supported.json
python -m pip check
python scripts/check_checkout_bytes.py
```

Optional release QA dependencies and commands:

```sh
python -m pip install --target .patchreplay/qa-deps jsonschema==4.23.0 PyYAML==6.0.2
python scripts/validate_artifacts.py --qa-deps .patchreplay/qa-deps
```

Browser screenshots were generated using `scripts/visual_check.cjs` with a
separately available Playwright installation and local Chrome. No Node package
is required by PatchReplay. Set `PATCHREPLAY_PLAYWRIGHT_MODULE` to an installed
Playwright module path and optionally `PATCHREPLAY_BROWSER` to a browser binary,
then run `node scripts/visual_check.cjs examples/evidence <screenshot-directory>`.

## Unverified and interpretation limits

- GitHub Actions execution, Linux/macOS runtime behavior and Python 3.11 execution
  were not tested locally. A workflow definition is not a CI pass.
- No hardened container/VM executor, external repository, adversarial-code run,
  real-project bug case, code-signing or producer attestation was tested.
- No second-machine replay, maintainer usability study or accessibility audit
  was performed. Browser QA used Chrome; it was not a cross-browser certification.
- No live AI integration or coding-agent effectiveness study was performed.
- Timeouts and two repeats are bounded observations. They do not establish
  determinism, total correctness, security or production readiness.

The next gate before accepting other users' patches is a hardened executor and
independently reviewed threat model, followed by real-provenance cases, remote
CI, and second-machine validation. See the [roadmap](../roadmap.md).
